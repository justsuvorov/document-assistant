# ВСК ДМС-ассистент Qwen Release — Бизнес-описание

## Что это

Сервис (REST API) для автоматического анализа запросов на ДМС. Корпоративный клиент отправляет документ с перечнем требований к страховому покрытию — система возвращает готовый ответ: по каждому пункту указано, есть ли оно в программе страхования, нет или покрывается частично.

---

## Проблема, которую решает

Менеджер страховой компании получает от корпоративного клиента документ на десятки или сотни позиций — список услуг, которые клиент хочет включить в полис ДМС. Вручную сопоставить каждый пункт с нормативными программами занимает несколько часов. При этом ошибки неизбежны, а ответ нужен быстро.

---

## Как работает

1. **Интеграция:** Клиентское приложение отправляет файл клиента на сервер API через эндпоинт `/api/update`.
   ```bash
   POST /api/update
   {
     "file_path": "/app/uploads/client.xlsx",
     "request_id": 1,
     "user_name": "Иванов И.И."
   }
   ```

2. **Оценка времени:** Опционально можно получить оценку объёма и времени обработки через `/api/estimate` без вызова LLM.

3. **Система анализирует каждое требование** через Qwen LLM, сопоставляя его с нормативной базой. Крупные документы разбиваются на чанки и обрабатываются последовательно. При ошибках сервиса (перегрузка, недоступность) система автоматически делает паузу и повторяет запрос.

4. **Ответ формируется в том же формате**, что и исходный файл — с тремя добавленными столбцами:
   - **Покрытие по программе** — цитата из нормативного документа
   - **Статус** — Есть / Нет / Частично (с цветовой маркировкой)
   - **Комментарий** — пояснение при частичном покрытии

5. **Результат сохраняется** в папке `uploads/` как `client_ответ.xlsx`.

6. **Кэширование:** Ответы LLM кэшируются в JSON-файл рядом с исходником. При необходимости можно пересобрать Excel из кэша через `/api/rebuild` — без повторного вызова модели.

## Ключевые характеристики

| | |
|---|---|
| **Интерфейс** | REST API (FastAPI) + Docker контейнер |
| **Форматы на входе** | `.xlsx`, `.xls`, `.docx`, `.doc`, `.pdf` |
| **Формат на выходе** | Тот же, что на входе (оригинал + 3 столбца) |
| **Многолистовые Excel** | Поддерживаются — требования ищутся по всем листам |
| **Масштаб** | Документы любого размера — от 10 до 300+ строк |
| **Нормативная база** | Загружается при каждом запросе — обновление без перезапуска сервера |
| **Провайдер ИИ** | Qwen 3.6-35B через OpenAI-compatible API |
| **Развёртывание** | Docker Compose, запускается на одном сервере |
| **Retry-логика** | Автоматическое повторение при перегрузке Qwen (до 3 попыток) |

## Преимущества

- ✅ **Автоматизация**: полностью автоматический анализ сложных документов
- ✅ **Скорость**: обработка 100+ строк за минуты (вместо часов вручную)
- ✅ **Точность**: структурированный ответ, стандартный формат
- ✅ **Гибкость**: поддержка Excel, Word, PDF
- ✅ **Надёжность**: автоматический retry при ошибках API
- ✅ **Масштабируемость**: кэширование ответов, возможность переобработки без LLM
- ✅ **Обновления базы**: нормативная база обновляется без перезапуска сервера

## Сверка деклараций с генеральным полисом (грузы)

Второй, независимый процесс в том же сервисе: сверка деклараций на перевозку груза с условиями генерального полиса страхования и дополнительных соглашений (ДС) к нему.

### Проблема, которую решает

Клиент подаёт декларации на перевозку в рамках действующего генерального полиса. Условия полиса со временем меняются дополнительными соглашениями — иногда несколькими подряд по одному и тому же пункту (например, объект страхования). Специалисту нужно вручную определить, какая редакция пункта действует на дату декларации, и сверить с ней каждое поле декларации. При десятках деклараций в месяц и накопившихся ДС это медленно и подвержено ошибкам.

### Как работает

1. **Матрица актуальных правил.** По указанному пути к папке полиса система находит генеральный полис (файл с именем «ГП …») и все ДС в подпапке «ДС» (файлы вида «ДС 3 (п.9, п. 7)» — номер ДС и номера изменяемых пунктов указаны прямо в имени файла), извлекает актуальный текст пунктов из каждого документа и сводит их в единую матрицу: по каждому номеру пункта остаётся текст из ДС с **наибольшим номером**, который его затрагивал. Оба пути — к файлу ген.полиса и к папке ДС — можно переопределить явно (например, если реальное расположение отличается от стандартного). Матрица считается один раз на папку полиса и кэшируется — пересчёт происходит только если состав файлов изменился.

2. **Сверка деклараций.** Декларации для сверки по умолчанию берутся из подпапки «Декларации» (рекурсивно, включая помесячные подпапки); путь к отдельному файлу или папке декларации можно также указать явно. Для каждой декларации система определяет:
   - **номер** — из имени файла;
   - **тип** — однострочная (одна перевозка) или мультистрочная (несколько перевозок в одном файле), по структуре документа, без обращения к ИИ.

3. **Логика сопоставления** берётся из папки `RECONCILIATION_RULES_BASE` — отдельной настройки от `NORMATIVE_BASE` ДМС-продукта. Это не каталог программ, а инструкция для ИИ: какие поля декларации сопоставлять с какими пунктами матрицы. Дополнительно учитываются **особые условия** — общий файл для всех клиентов и/или файл конкретного клиента в его сетевой папке — с отклонениями от стандартного процесса сверки.

4. **Результат** формируется по фиксированной форме (одна строка = одно поле декларации, статус «совпадает / не совпадает / не знаю») и сохраняется рядом с исходным файлом декларации: `«{номер} – результат проверки.xlsx»`. Для мультистрочной декларации это один файл с несколькими группами строк — по одной группе на перевозку, с нумерацией `200/1`, `200/2` и т. д. в первом столбце.

5. **Двуязычность.** Декларации и генеральный полис могут быть на русском, английском или на обоих языках одновременно — парсинг документов и промпты ИИ это учитывают.

### Ключевые характеристики

| | |
|---|---|
| **Эндпоинт** | `POST /api/reconcile` |
| **Вход** | Путь к папке полиса (+ опциональные override на файл полиса/папку ДС) и, опционально, путь(-и) к декларациям (без ограничения по количеству) |
| **Структура папки полиса** | `ГП ....docx` — ген.полис; `ДС/ДС N (п.X, ...).docx` — доп. соглашения; `Декларации/{месяц}/...` — декларации по умолчанию |
| **Кэш матрицы правил** | `_matrix_cache.json` в папке полиса, инвалидация по составу/датам файлов |
| **Формат результата** | Фиксированный шаблон `document_assistant/cargo/templates/reconciliation_form.xlsx` |
| **Статусы сверки** | Совпадает / Не совпадает / Не знаю (в отличие от ДМС-продукта — Есть/Нет/Частично) |
| **Определение типа декларации** | Детерминированно, по структуре документа (без вызова ИИ) |
