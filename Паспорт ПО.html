GUI собирается в одном из двух режимов: единый .exe (проще переносить) или папка с exe и библиотеками рядом (устойчивее к антивирусам/политикам, блокирующим самораспаковку во временную папку). В обоих случаях функциональность одинакова — раздавать нужно то, что фактически собрано: один файл или папку целиком.

2Требования к операционной системе

ОСWindows 10 (версия 1809 и новее) или Windows 11, 64-разрядная
Причина требованияGUI построен на Qt6 — эта версия Qt не поддерживает Windows 7/8.1 и ранние сборки Windows 10; на них загрузчик не найдёт нужные системные API
Права пользователяобычные, без администратора — оба .exe не требуют установки, запускаются из любой папки
Сторонние рантаймыне требуются — Visual C++ Runtime уже упакован внутрь дистрибутива обеих программ

3Требования к аппаратному обеспечению

Распознавание и сопоставление текста выполняет удалённая LLM — локально нагрузка ограничена разбором Excel/Word/PDF и GUI, поэтому требования умеренные. Ориентировочные значения, не результат нагрузочного теста.

4Требования к сети

НаправлениеКуда
GUI → API-сервис 127.0.0.1:8001 обязательно
API-сервис → модель ИИ интернет/VPN до адреса модели (*.ai-api.vsk.ru) обязательно
API-сервис → общие особые условия корпоративная сеть, сетевой путь вида \\fstorfs\... только «Сверка грузов»
API-сервис → папка полиса клиента сетевой каталог с ген. полисом, ДС и декларациями; требуется доступ на чтение и запись — результат сверки сохраняется рядом с декларацией только «Сверка грузов»
⚠

Порт 8001 должен быть свободен на машине — если его уже занимает другой процесс, API-сервис не запустится. Порт можно сменить в app/config.json (поле api_base_url) при условии одновременной правки на стороне запуска сервиса.

⚠

При работе через корпоративный прокси адреса 127.0.0.1 и localhost обязаны быть в списке исключений NO_PROXY. Иначе обращение GUI к локальному API уходит на прокси и не возвращается — внешне это выглядит как «GUI не видит сервис», а не как проблема сети.

Настройки прокси задаются в файле proxy.env рядом с дистрибутивом; запуск через run-all.bat подставляет их автоматически и принудительно добавляет localhost в исключения.

7Порядок запуска

1
Запустить API-сервис.exe. Дождаться в консоли строки Uvicorn running on http://127.0.0.1:8001. Окно не закрывать.
2
Запустить ВСК ДМС-ассистент.exe (или exe из папки, если сборка в режиме «папка рядом с DLL»).
3
Выбрать вкладку — «ДМС» или «Сверка грузов» — и работать по соответствующей инструкции пользователя.

8Известные ограничения и диагностика

  • «DLL load failed while importing QtCore» при запуске GUI — на части машин однофайловая сборка (самораспаковка во временную папку при каждом запуске) теряет часть библиотек из-за антивируса или политик безопасности. Решение — сборка в режиме «папка»: все библиотеки лежат рядом с exe постоянно, распаковка не требуется.
  • Общие особые условия («Сверка грузов») подключаются автоматически только при наличии доступа к корпоративной сети в момент запуска API-сервиса — при недоступности сети сверка всё равно проходит, но без этого блока условий.
  • Время сверки пропорционально числу перевозок. Мультистрочная декларация обрабатывается по одной перевозке за вызов модели. Однострочная (вертикальная) обрабатывается целиком одним вызовом.
  • Матрица правил по умолчанию пересобирается при каждом запуске (галочка в интерфейсе установлена). Это дороже по времени — требуется по одному вызову модели на генеральный полис и на каждое ДС, — но исключает работу по устаревшему кэшу. Снимать галочку допустимо, только когда полис и ДС заведомо не менялись.
  • При сбое отдельного документа обработка продолжается. Недоступность модели или нечитаемый файл приводят к пропуску источника, а не к остановке всего запуска. В этом случае в логе появляется строка «Матрица правил построена без N источник(ов)» — отчёт при этом внешне выглядит нормальным, но сверка идёт по неполным правилам, и принимать его как готовый нельзя.
  • Распознавание вида декларации опирается на наличие колонки «№ п/п». Мультистрочная декларация без такой колонки будет обработана как одна перевозка. Фактически выбранный вид печатается в лог по каждому файлу.
  • Требования к аппаратному обеспечению и оценки времени приведены ориентировочно и не являются результатом нагрузочного тестирования.
