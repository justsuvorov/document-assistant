Сверка деклараций с генеральным полисом

Как настроить и запустить сверку деклараций на перевозку груза с условиями генерального полиса и дополнительных соглашений (ДС). Инструкция охватывает только вкладку «Сверка грузов» — модуль ДМС здесь не рассматривается.

01Что должно быть на месте

Единый комплект из двух программ — API-сервис работает в фоне, приложение с интерфейсом обращается к нему.

API-сервис.exeФоновый сервис. Принимает запросы на сверку, обращается к модели ИИ, сохраняет результат. Работает без окна — только чёрная консоль с логом.
ВСК ДМС-ассистент.exeЕдиное приложение с интерфейсом. Несмотря на название, внутри есть вкладка «Сверка грузов» — именно её нужно использовать.
.envФайл настроек рядом с API-сервис.exe. В нём — адрес модели ИИ, шаблоны промптов и общий файл особых условий. Настраивается один раз.
⚠

Шаблон формы результата (reconciliation_form.xlsx) уже встроен в API-сервис.exe — отдельно копировать его не нужно.

02Разовая настройка .env

Делается один раз тем, кто разворачивает приложение. Дальше пользователь этот файл не трогает.

⚠

Провайдер модели должен быть указан явно. Значение по умолчанию в коде — ollama (локальная модель), которой на рабочей машине нет.

В .env обязательно: AI_PROVIDER=qwen — или vsk, если используется альтернативный API.

ПараметрЧто означает
AI_PROVIDERобязательноqwen или vsk — какой API модели использовать
QWEN_API_URL / VSK_API_URLпо умолчанию окадрес модели — уже заполнен в поставке
VSK_API_KEYпо умолчанию октокен доступа — уже зашит, менять не нужно
MATRIX_AI_ROLE
MATRIX_PROMPT_TEMPLATE		по умолчанию окинструкция модели для извлечения пунктов из ГП и ДС (шаг 1 сверки)
RECONCILIATION_AI_ROLE
RECONCILIATION_PROMPT_TEMPLATE		по умолчанию окинструкция модели для сверки декларации с матрицей правил (шаг 2)
RECONCILIATION_RULES_BASEнеобязательнофайл с дополнительными правилами сверки (какие поля с какими пунктами сопоставлять). Пусто — модель решает сама по данным полиса
SPECIAL_CONDITIONS_GLOBAL_PATHпо умолчанию окобщий файл особых условий для всех клиентов, подключается к каждой сверке автоматически (см. ниже)
DECLARATIONS_MONTH_FORMATпо умолчанию ок%Y-%m — формат имени месячной подпапки в «Декларации/»
📡

Общий файл особых условий сейчас указывает на сетевой путь:

SPECIAL_CONDITIONS_GLOBAL_PATH=\\fstorfs\disk_m\БОС_ФСЦ_УПиСД\ДГ\Информационный\ДпГ УПиСД ФСЦ.xlsm

Он должен быть доступен с машины, где запущен API-сервис.exe (корпоративная сеть). Если файл недоступен — сверка всё равно пройдёт, просто без общих особых условий.

ℹ

Поля NORMATIVE_BASE, AI_ROLE, AI_PROMPT_TEMPLATE относятся к модулю ДМС и в сверке грузов не используются — но без них приложение вообще не запустится. Не удаляйте их из .env, даже если работаете только с грузами.

03Организация папки полиса

Один клиент — одна папка, в любом месте на диске. Приложение само найдёт в ней всё нужное по названиям файлов.

Папка полиса ООО «Клиент»/ ├── ГП Договор № 2506Q13GR2182.docx ← имя обязательно начинается с «ГП» ├── ДС/ ← подпапка для доп. соглашений │ ├── ДС 1 (п.9).docx ← правит пункт 9 │ ├── ДС 2 (п.5).docx ← правит пункт 5 │ └── ДС 3 (п.9, п.7).docx ← более новый ДС побеждает при совпадении пункта ├── особые условия — ООО Клиент.xlsx ← необязательно, находится по слову в имени └── Декларации/ ├── 199.xlsx ├── 200.xlsx └── 2026-06/ ← можно группировать по месяцам ├── 508 совпадает.xls └── 511 не совпадает.xlsx
Ген. полисИмя файла должно начинаться с «ГП». Формат: .xlsx, .xlsm, .xls, .docx, .doc, .pdf.
ДСПодпапка «ДС» внутри папки полиса. Имя файла: «ДС {номер} (п.{X}, п.{Y})» — номер обязателен, номера пунктов в скобках желательны для точного сопоставления. При совпадении номера пункта побеждает ДС с бо́льшим номером.
ДекларацииПодпапка «Декларации» — можно класть файлы напрямую или раскладывать по месячным подпапкам любой вложенности, сканируется рекурсивно.
Особые условия клиентаНеобязательный файл прямо в папке полиса, в имени которого встречается «особые условия» или «особых условий». Если такого файла нет или нужен другой — выбирается вручную в приложении.

04Запуск

Порядок важен: сервис должен подняться раньше приложения.

1

Запустите API-сервис.exe

Дождитесь в консоли строки Uvicorn running on http://127.0.0.1:8001. Окно не закрывать — сервис должен работать всё время, пока идёт сверка.

2

Запустите ВСК ДМС-ассистент.exe

Откроется окно с двумя вкладками наверху.

3

Переключитесь на вкладку Сверка грузов

4

Выбрать папку — укажите папку полиса

Ту, что собрана по схеме из раздела 3.

5

Особые условия клиента — по необходимости

Если авто-поиск не нашёл файл или нужен другой — Выбрать рядом с полем.

6

Выбрать декларации — отметьте файлы для сверки

Можно выделить сразу несколько. Кнопка Добавить ещё дополняет список, не сбрасывая уже выбранное.

7

При необходимости — «Пересчитать матрицу актуальных правил заново»

Матрица правил (пункты ГП + ДС) кэшируется по папке полиса. Галочку включайте, только если задним числом правили ГП или ДС и файлы не изменились по дате — иначе кэш обновится сам.

8

Начать сверку

Кнопка сменится на «Сверка…», внизу пойдёт счётчик времени. Результат по каждой декларации — отдельный файл, открывается кнопкой Открыть прямо из приложения.

05Как читать результат

Файл результата — тот же шаблон, что и раньше, с закреплённой строкой заголовка. Цвет в столбце «Результат проверки» соответствует статусу.

совпадает — поле декларации полностью соответствует пункту полиса
не совпадает — есть расхождение, требует внимания
не знаю — модели не хватило данных для однозначного вывода

06Частые вопросы

Почему сверка идёт долго при большой декларации?
Каждая строка перевозки в мультистрочной декларации — это отдельный запрос к модели. Декларация на 10 перевозок — это 10 обращений подряд, отсюда и время.
Приложение не находит «Особые условия клиента» само
Автопоиск смотрит только на имя файла в папке полиса — там должно быть слово «особые условия» или «особых условий». Если файл называется иначе, выберите его вручную кнопкой «Выбрать».
Нужно ли пересчитывать матрицу правил при каждой сверке?
Нет. Матрица строится один раз на папку полиса и кэшируется — повторная сверка деклараций той же папки использует готовый результат. Пересчёт нужен только если правки в ГП/ДС не отразились на дате изменения файла.
